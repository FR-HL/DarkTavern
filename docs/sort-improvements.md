# 仓库自动整理 · 后续优化方向

> 背景：用户反馈自动整理"操作复杂繁琐、容易出错"。2026-08 已完成第一阶段
> （整理前自动刷新数据，去掉"回选角界面重选角色"步骤）。本文档记录调查发现的
> 其余问题与改进方向，按优先级排列，供后续迭代参考。

## 已完成（第一阶段）

- 整理前自动刷新数据：开始整理时自动切换游戏顶部栏页面（商人页→仓库页），
  触发游戏重新下发全量仓库快照，抓包自动更新本地数据。
  单仓 / 全仓 / 跨仓 / 堆叠合并四条入口全部接入（`autoRefreshBeforeSort` 设置）。
- 「角色仓库」页"一键更新"按钮：手动触发同样的刷新流程。
- 移除所有"回角色选择界面重选角色"的旧引导文案。

## 待办

### P0 · 防错（最容易造成物品损失的点）

1. **热键路径补角色一致性校验**
   - 现状：按钮路径有 `confirmCharacter` 拦截（SortControl.vue），但全局热键
     Ctrl+R / Ctrl+F12（electron/main.js `registerSortHotkeys` / `registerCrossHotkeys`）
     直接用持久化的 `sort_char_id/sort_stash_id` 执行，跳过一切确认。
   - 方案：把角色一致性校验下沉到 Python 后端（抓包已知游戏内当前角色
     `last_snapshot_character_id`），所有入口走同一校验；不一致时拒绝执行并
     返回明确错误（悬浮球提示），而不是静默整理错仓库。
   - 自动刷新已提供 `mismatch` 信号（refresh_character_data 返回值），
     可作为该校验的数据源。

2. **执行闭环验证**
   - 现状：整理是开环的——全靠内存网格镜像，没有来自游戏的执行确认。
     `move_verifier.py`（截图差异验证）和 `GridSnapshot.detect_drift`
     已实现但未接入主流程。
   - 方案：把 drift 检测接入回放阶段；至少在中止/异常后用截图比对确认
     网格状态，给出"哪些物品可能错位"的报告。

3. **取消后的恢复路径**
   - 现状：整理中止 = 仓库半整理状态 + 本地数据过期，用户需手动重走刷新链路。
   - 方案：取消后自动提示"数据已过期，是否刷新并重试"；现在自动刷新已内置，
     可直接在取消结果里加"重新整理"按钮（数据会在开始时自动刷新）。

### P1 · 流程简化

4. **选择与执行合并**
   - 现状：角色/仓库在「角色仓库」页选择，"开始整理"在「仓库配置」页，
     靠 App.vue 共享状态桥接；执行页看不到当前选中目标的直观展示。
   - 方案：在仓库可视化网格上方直接提供"整理此仓库"按钮；
     「仓库配置」页退化为高级选项页。

5. **跨仓整理配置预设化**
   - 现状：6 个步骤开关 + 5 选 1 位置策略 + 手动归类映射（6 类 + 杂物 5 子类），
     互斥关系靠 UI 保证，配置以 JSON 持久化后被 Ctrl+F12 隐式使用。
   - 方案：提供"一键归位 / 深度整理"等预设，高级映射折叠到"高级"区；
     热键触发前在悬浮球展示将要使用的角色与配置摘要。

6. **校准流程减负**
   - 现状：Tab 坐标校准需对每个 Tab 重复"游戏内点标签→回工具点记录"，
     且必须全部记录完才能保存；像素跟随、快速放置各有一套校准。
   - 方案：默认全部走一键自动校准（像素跟随已有），手动记录仅作兜底；
     快速放置校准改为自动验证（用抓包数据核对预测落点，不需要肉眼确认）。
   - 进展：快速放置校准已移除（开发端点 quickplace-test 全链路删除）；
     仓库标签校准入口已从「仓库配置」页合并至「角色仓库」页首次校准卡片的
     「自定义」折叠区（含一键自动校准 / 手动记录 / 保存清除 / 标签点测）。

### P2 · 环境与可靠性

7. **tshark 内置打包**
   - 现状：依赖用户安装 Wireshark 并勾选 tshark，红点时还要手动选路径，
     是最常见的安装踩坑点。
   - 方案：随安装包内置 tshark.exe（注意 GPL 合规：tshark 为独立可执行文件，
     不链接进主程序），彻底去掉该步骤。

8. **UIPI 权限自动化**
   - 现状：游戏管理员运行而工具没有时 SendInput 被静默丢弃，
     靠检测 + 警告条提示。
   - 方案：检测到游戏是管理员进程时，引导用户一键以管理员重启本工具
     （而非只给文字提示）。

9. **速度档与可靠性**
   - 现状：极速档官方自述偶发漏操作，出问题只能降速。
   - 方案：结合闭环验证（第 2 条）做"漏放自动补放"，或按步骤类型动态调速
     （关键步骤慢、空拖快）。

10. **状态感知统一**
    - 现状：SortControl 每 1s 轮询 sort-status、StashPane 每 5s 轮询抓包状态、
      悬浮球每 2s 推送；整理开始后主窗口自动最小化，出问题时排查路径长。
    - 方案：统一走 WebSocket 事件推送（stash/events 已有基础设施）；
      整理日志实时可见，而不是结束后才看到。
